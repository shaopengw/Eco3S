# Skill S6：反复打同样补丁

## 何时使用

- 同一修改在多个轮次中反复出现
- 上一轮号称修复了，但问题依旧
- 诊断文本只 echo 原结论，没有引用修改后文件的内容

## 根因

通常是因为根因校验阶段**没有读实际修改后的文件**，只根据原诊断文本或记忆下结论。

## 必查步骤

1. **读上一轮修改后的目标文件**
   - 用 `read_file` 读 `simulator.py`、相关 YAML 等。
   - 确认上一轮补丁是否真的存在、是否生效。

2. **检查重复方法 / 死代码**
   - 同一个方法是否被定义了多次。
   - 是否存在永远不会被调用的旧版本。

3. **检查诊断是否携带新证据**
   - 新一轮诊断必须引用具体 Traceback、CSV 数据、或修改后文件内容。
   - 禁止只输出“我认为还是 XXX 问题”。

4. **清理后再补丁**
   - 若目标文件已腐烂，在 `files_to_modify` 中第一项写“清理/重写该方法/文件”。

## 常见修复

- 删除重复的旧方法。
- 重写整个方法而不是继续增量打补丁。
- 在 `verify_root_cause` 阶段强制 `read_file` 修改后文件。

## 禁止

- 不读文件就重复同样的修改建议。
- 在已有重复方法的基础上继续叠加。

## 验证

- 修改后文件 AST 中目标方法只出现一次。
- 重新跑最小配置，确认原问题指标变化。
- 再次诊断时不再提出同一补丁。
