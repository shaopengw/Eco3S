# Skill S8：审计反馈（改代码前先读审计日志）

## 何时使用

- 上一轮提出的改动被**审计 Agent 驳回**，要重新生成。
- 评估报告里出现 `audit` 相关提示，或日志里有 `audit_ledger` 记录。

## 背景

优化阶段，你（CodeFixer）提出的每处改动，会先经过审计 Agent 两道关卡才落盘：

- **第一关·匹配快检**：查你用的方法名/属性是否真实存在。最常见的驳回是"你调用了一个本类里不存在的方法"（编造方法名）。
- **第二关·语义审查**：查这处改动是否真能解决问题、会不会数值爆炸、是否符合设计。

驳回理由都写在审计日志里：`projects/<项目名>/audit/audit_ledger.json`。

## 必查步骤

1. **先读审计日志**
   - 读 `audit_ledger.json` 的 `复核记录` 最近几条，看清楚上一轮**为什么被驳回**。
   - 重点看 `原因` 和 `修正建议` 字段。

2. **照建议改，别再犯同样的错**
   - 如果驳回原因是"方法名不存在"，按 `修正建议` 里给的真实方法名改（建议里通常已经指出最接近的真名）。
   - 必要时用 `read_file` 打开对应接口文件（如 `src/interfaces/ipopulation.py`）确认真实方法签名。

3. **绝不重提"已驳回清单"里的改法**
   - 日志的 `已驳回清单` 列出了被否过的改法签名。再提一遍只会被直接驳回、浪费一轮。

## 禁止

- 不读审计日志就重新生成，结果又编一个不存在的方法名。
- 重复提交 `已驳回清单` 里的改法。

## 验证

- 重新生成的改动里，所有 `self.xxx()` 调用都能在真实代码/接口中找到。
- 审计日志里的 `原因` 和 `修正建议` 中引用的方法名/属性名，都必须在源码中真实存在。
- 审计日志这一处的结论从"驳回"变成"通过"。
